# Metadata workload authority

The public protocol metadata service must use a dedicated login that can read only `orio_master.assets`, `orio_master.elections` and `orio_master.current_election`, with schema usage and no ORIO write, ledger-read, executable financial-function, sequence, ownership or administration authority. This module creates no hosted role, secret, IAM grant, network change or deployment.

Before listening, the server verifies TLS and authenticates the actual database identity through `assertProtocolReaderIdentity`. Known administrator URLs are rejected before connecting. A failed startup check produces a generic credential-safe error and closes the pool; it does not expose a healthy listener backed by an administrator identity. Initial database unavailability or a wrong TLS hostname also stops startup, so the workload orchestrator must retry appropriately.

Each actual registry read repeats authority verification and reads the registry on the same client in one read-only transaction with `pg_catalog` search path. Reachable membership roles are checked, including NOINHERIT memberships and the authenticated session behind SET ROLE. Elevated flags, RDS administration roles, database/schema ownership and excess ORIO permissions reject the request. Missing required registry access also rejects. A later privilege change causes generic503 readiness/registry responses without returning database details. Static policy and liveness routes do not gain financial authority.

These are deployment and request guardrails, not a way to make administrator credentials safe inside a compromised application. Provision the real login and its AWS secret/IAM access separately with least privilege; never supply a migration-owner or RDS administrator secret to the application. A privileged database administrator can change grants and data and is not independently authenticated by these checks.

Verification includes real isolated PostgreSQL sessions with dedicated logins, direct and latent membership privileges, schema/database owners, masked privileged sessions, permission revocation and per-request rechecking. The Linux container runs as UID1000 over verified TLS, serves the paused public metadata with the restricted login, and exits on administrator credentials or an incorrect TLS hostname without printing its password. Local verification passes223 tests plus the container smoke test and strict TypeScript.

The hosted application login, protected credential delivery and public workload deployment remain unfinished. Financial routes and mainnet execution remain disabled. The separately prepared SQL qualification package remains pinned to its reviewed source and still awaits the private-access/cost approval; this service safeguard does not execute that package or change its scope.
